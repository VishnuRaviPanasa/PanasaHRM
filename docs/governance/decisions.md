# Decision Log (DEC-NNN)

Non-architectural decisions: waived findings, deferred scope, accepted risks, convention picks.
**Architectural** decisions go in `docs/adr/` instead.

Every waiver needs a reason, an owner and a review date. Silence is not a waiver.

|---|---|---|---|---|---|
| DEC-001 | 2026-09-08 | `CLAUDE.md` carries **no phase or status line** | The plan (section 24.2) requires zero mutable state in `CLAUDE.md`; a hardcoded phase is exactly the line that goes stale and misleads a future session. Status lives in `.claude/state/`. This supersedes the plan section 48 wording for Task 1 | Claude | - |
| DEC-002 | 2026-09-08 | **ESLint deferred to Phase 2** | There is no TypeScript to lint, and `eslint-plugin-boundaries` needs the module paths that Phase 2 creates. Configuring it now would be speculative and untested | Claude | Phase 2 |
| DEC-003 | 2026-09-08 | **Hooks deferred to Task 2** | Hooks ship together with their scripts so each can be tested the moment it is added. A hook entry pointing at a missing script fails silently, which is worse than no hook | Claude | Task 2 |
| DEC-004 | 2026-09-08 | **Hook scripts are Node, not Python** | The org precedent (Thredd) used Python with a shell shim, because `python3` on Windows is often a Microsoft Store stub that fails an import test. `node` has no such ambiguity and is already the project runtime, so hooks are one language fewer to maintain | Claude | - |
| DEC-005 | 2026-09-08 | **`confidence_score` is NOT a gate input** (envelope v2) | Self-reported confidence only catches the agent honest enough to admit uncertainty. The gate is `critical_count == 0` plus deterministic checks. Confidence is kept as a triage hint for reading order | Claude | - |
| DEC-006 | 2026-09-08 | **Invocable workflows are skills, not `.claude/commands/`** | Skills are the current mechanism, take precedence where both exist, and support `!` shell injection (used by `session-brief` to ground the model in live state) and `disable-model-invocation` for side-effecting flows | Claude | - |
| DEC-007 | 2026-09-08 | **Only two agents may write, and neither writes application code** | `migration-author` is confined to migrations and the schema mirror; `test-author` to tests and fixtures. With no peer reviewer, an agent writing business logic that another agent approves is a closed loop with no human in it | Claude | Reconsider if a second developer joins |
| DEC-008 | 2026-09-08 | **Stop-hook typecheck and push-gate artifact deferred to Phase 2** | There is no TypeScript to check and no code to gate. A hook that no-ops is indistinguishable from one that is broken, which is worse than a documented absence | Claude | Phase 2 |
| DEC-009 | 2026-09-08 | **Dev-stack host ports default to a high range** (55432, 56379, 59000/1, 58080), overridable by env var | A local PostgreSQL already owns 5432 on at least one developer machine, so the standard port makes `docker compose up` fail out of the box. All bind to 127.0.0.1 only | Claude | - |
| DEC-010 | 2026-09-08 | **Postgres volume mounts at `/var/lib/postgresql`, not `/var/lib/postgresql/data`** | PG18's image changed this. The image places data in a major-version subdirectory so `pg_upgrade --link` works without mount-boundary problems. Mounting at `.../data` makes an 18+ container refuse to start - found by it actually refusing to start | Claude | - |
| DEC-011 | 2026-09-08 | **Migrations are forward-only; there is no `down`** | Production rollback is deploying the previous image against the new schema, which is what makes expand/contract non-optional rather than advisory. | DEC-012 | 2026-09-08 | **The migration runner enforces checksums** and refuses to apply anything if an already-applied migration was edited | Editing an applied migration is how two environments silently diverge, with nothing reporting it | Claude | - |
| DEC-013 | 2026-09-08 | **The migration runner uses `psql` only, not the app's node_modules** | It must work before `npm install`, in CI, and during an incident. `psql` is already required to operate this system | Claude | - |
| DEC-014 | 2026-09-08 | **Migration checksums normalise line endings before hashing** | A Windows checkout has CRLF and a Linux/CI checkout has LF, so hashing raw bytes made the SAME migration report drift on every CI run. Found by it reporting drift immediately after a clean apply | Claude | - |
| DEC-015 | 2026-09-08 | **`psql` output is CR-stripped before parsing** | Same CRLF class, second location: per-row values kept a trailing CR, so a stored checksum never compared equal to the recomputed one | Claude | - |
